# Rollcall QR Attendance

A compact, server-validated QR attendance system using Google Sheets as storage.

## What is included

- One instructor login using `INSTRUCTOR_PASSWORD`.
- Student check-in with only name and batch.
- Server-side course mapping, Asia/Kolkata date/time, validation, duplicate protection, and signed 30-minute QR sessions.
- Ten subject tabs, a roster-driven absent finalization action, and a synchronized `Percentage` tab.
- Responsive instructor dashboard and mobile-first student page.

## 1. Create the Google spreadsheet

Create one spreadsheet and add these tabs exactly:

- `Students`
- `Percentage`
- `Subject 1` through `Subject 10`

Use these headers in `Students`:

```text
Student ID | Student Name | Batch
```

The app automatically adds a new student to this tab the first time that student marks attendance. The `Student ID` is generated by a Google Sheets formula, not by the server. Existing students are matched by name and batch, so duplicate roster rows are not created. Only P1-P10, J1-J10, and D1-D10 are accepted. Use these headers in every subject tab:

```text
Date | Time | Student Name | Batch | Course | Subject | Status | Attendance Source | Session ID
```

Use these headers in `Percentage`:

```text
Student Name | Batch | Course | Subject | Attended Classes | Total Classes | Subject Percentage | Full-Course / Overall Percentage
```

Share the spreadsheet with the Google service-account email as **Editor**, then copy the spreadsheet ID from its URL.

## 2. Configure and run

```powershell
Copy-Item .env.example .env
```

Edit `.env`:

- `INSTRUCTOR_PASSWORD`: the single password used by the instructor.
- `SESSION_SECRET`: a long random value.
- `GOOGLE_SPREADSHEET_ID`: spreadsheet ID.
- `GOOGLE_SERVICE_ACCOUNT_JSON`: the full service-account JSON on one line.
- `APP_URL`: the public HTTPS URL used in QR codes after deployment.
- `MIN_ATTENDANCE_PERCENTAGE`: optional minimum threshold for the student attendance warning. Defaults to `75`.

To create a structure-only copy before moving the app to a new Google Spreadsheet file:

```powershell
$env:SOURCE_GOOGLE_SPREADSHEET_ID = "current-spreadsheet-id"
$env:NEW_SPREADSHEET_NAME = "Rollcall Attendance Copy"
npm run migrate:sheet
```

The command creates a native Google Sheets copy, preserving tabs, colors, formulas, filters, validations, column widths, and formatting. It clears all rows below the first row, so old attendance records and roster data are not carried over. Copy the new ID printed by the command into `GOOGLE_SPREADSHEET_ID`, then restart the app. The service account must have access to the source spreadsheet and permission to create a copy in Google Drive.

Then run:

```powershell
npm install
npm start
```

Open `http://localhost:3000`. The instructor logs in with the configured password. Students use the QR URL generated by the dashboard.

## Attendance lifecycle

1. Instructor selects a subject and optional batch scope, then generates a QR.
2. The QR is valid for 30 minutes and cannot be edited without invalidating its signature.
3. Students submit a name and batch. The server maps the course and writes `Present`.
4. Instructor clicks **Close session and mark absences**. Every roster student in scope without a record for the server date receives `Absent`.
5. The `Percentage` tab is rebuilt from present and absent rows, so absences count toward total classes.
6. After marking attendance, students can check their own subject attendance. The lookup uses the subject matrix date columns, excludes future dates, and matches by name plus batch.

Close a session only after the class is finished. Past records are not exposed through correction controls. Google Sheets itself should be restricted to trusted administrators.

## Deployment

Deploy the Node process to a host that supports environment variables and HTTPS (Render, Railway, Fly.io, or a VM). Set `APP_URL` to the deployed HTTPS origin. Keep `.env` out of git and never place service-account JSON in `public/`.

For a production deployment, use a persistent session store and a managed rate limiter at the hosting layer. The app's instructor cookie is HttpOnly, SameSite=Strict, signed, and expires after eight hours.

## Smoke test checklist

- Login with the configured password and reject an incorrect password.
- Generate a QR for a subject and submit a valid student.
- Submit the same student again and confirm the duplicate message.
- Try `Rahul123`, `Rahul@`, and `P11`; all must be rejected.
- Close a scoped session and verify missing roster students receive `Absent`.
- Verify the Percentage tab reports `17 / 20 = 85.00%` for a 17-present, 3-absent case.
- Wait for or temporarily set `QR_MINUTES=1` and confirm expired QR submission is rejected.
